# 공통 환경 — 문가원

- 서비스·IP·권한·네트워크는 루트 `docker-compose.yml`에서 관리합니다.
- `client.Dockerfile`은 관리자·비인가 사용자 테스트용 공통 이미지입니다.
- 외부망·내부망은 각자의 로컬 Docker 안에 생성합니다.
- 최소 틀의 목표는 네 컨테이너 기동·IP 확인·웹서버 자체 응답입니다.
- 브라우저 시연을 추가할 때는 웹서버 직접 공개 대신 방화벽 경유 경로를 설계합니다.

## 기본 실행 확인 — 2026-11-17

아래는 초기 틀 당시의 기록입니다. 담당 코드 통합 이후의 현재 검증은 [테스트 안내](../tests/README.md)를 참고하세요.

문가원의 macOS 환경에서 `docker compose up -d --build` 실행 후 Docker Desktop의 Logs·Inspect로 확인했습니다. 실행 이미지는 Linux / ARM64이며, GitHub에 연결된 `network_project` 폴더의 Compose 설정을 사용했습니다.

| 대상 | 실행 상태 | 확인한 네트워크·IP |
| --- | --- | --- |
| `firewall` | running, 공통 초기화·TODO 스크립트 호출 완료 | 외부망 `172.30.10.254`, 내부망 `172.30.20.254` |
| `web` | running, healthy, 자체 HTTP 200 응답 | 내부망만 연결, `172.30.20.10` |
| `client-admin` | running | 외부망만 연결, `172.30.10.10` |
| `client-guest` | running | 외부망만 연결, `172.30.10.20` |

- 웹서버 헬스체크는 실패 횟수 0이며, Nginx 로그에서 `127.0.0.1`의 `GET /` 요청에 대한 HTTP 200 응답을 확인했습니다. 방화벽 경유 접속은 아직 검증하지 않았습니다.
- 호스트에 공개된 포트는 없습니다. 웹서버 Inspect의 `80/tcp: null`은 호스트 포트에 연결되지 않았다는 의미입니다.
- 방화벽 로그는 `[init]` → `[TODO 03]` → `[TODO 04]` → `[ready]` 순서로 출력됐습니다. 실제 규칙 목록·패킷 카운터와 재생성 후 동작은 아직 확인하지 않았습니다.
- HTTP 전달·차단 정책과 관리자 IP·SSH 인증은 구현 대기입니다. 담당 코드 통합 후 정상 접속·타 포트 차단·인증 실패·비인가 IP 차단을 각각 검증합니다.
- 다른 운영체제·팀원 PC에서의 실행은 아직 검증하지 않았습니다.
